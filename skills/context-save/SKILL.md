# 上下文保存协议

## 为什么

这个项目的工作环境（OpenCode/Trae）会在上下文消耗到一定程度时压缩会话。
压缩后我会丢失当前任务的细节，导致：

- 用户需要重复说明需求
- Bug 修复到一半要重来
- 设计讨论的上下文丢失

## 保存时机

**每天至少保存一次。** 以下情况必须触发保存：

1. **会话开始时** — 读取 `project/` 下最新的进度文件，恢复上下文
2. **完成一个逻辑单元后** — 每次修完 bug、实现完功能、讨论完设计方案后
3. **大型操作前** — 跑测试、大规模重构、批量修改前
4. **用户明确要求时**

## 保存位置

```
project/
├── current.md     ← 当前会话进度（每次覆盖更新）
├── 2026-06-03.md  ← 每日日志（追加）
└── archive/       ← 历史存档
```

## current.md 模板

```markdown
# 当前进度 — 2026-06-03

## 今日目标
- [ ] 任务 1
- [ ] 任务 2

## 进行中
- 正在做什么
- 遇到什么问题
- 下一步打算

## 已提交
- commit hash: 改动说明
- commit hash: 改动说明

## 未提交
- 文件路径: 改动内容

## 待办
- [ ] 后续需要做的事
- [ ] 需要注意的事项

## 决策记录
- 关键决策和理由
```

## 压缩前检查清单

当感觉上下文接近上限时，依次检查：

1. [ ] 当前进度写入 `project/current.md`
2. [ ] 今日工作追加到 `project/YYYY-MM-DD.md`
3. [ ] 更新 `PROJECT_MEMORY.md` 中的开发历史
4. [ ] 确认所有代码变更已 stage（如果有必要提交）
5. [ ] 记录下下一步该做什么
